# 京都駅周辺 コマ地図メーカー

三崎港版とは別のリポジトリ・ブラウザ保存領域で動く静的Webアプリです。京都駅北側を発着し、東本願寺・西本願寺・渉成園・梅小路公園・東寺の付近を巡るCP5か所のコースを用意します。実際の通行可否や営業時間は実施前に確認してください。

## 動作確認済み

実際のOpenStreetMapデータ（道路7,689本・経路用ノード26,853点）を同梱しています。基本のコマ地図生成に外部APIキーやデータ再取得は不要です。サンプルは後半の訪問順により約5.78〜5.99km、全175〜180コマ、省略版83〜93コマ、CP5か所になります。サンプル地点の参照元OSM IDと道路上への補正距離もデータに記録しています。

京都の実ルートを使うテストと、ブラウザでの生成・全表示切替・地図番号照合・手元の画像追加・JSON入出力・再読み込み・参加者表示・PDF出力を確認済みです。実際のGoogle Street View APIへの課金を伴う画像取得は行っていません。通行可否・営業時間などの現地確認は別途必要です。

## セットアップ

通常の起動はPython 3だけで可能です。データ更新・テストではNode.jsも使用します。外部パッケージのインストールは不要です。

```bash
cd /workspaces/kyoto-koma-map
python3 -m http.server 8000 --directory site
```

クラウド環境内のチェックアウトは `/workspace/kyoto-koma-map`、Codespacesの標準パスは `/workspaces/kyoto-koma-map` です。Codespacesではポート8000の「Open in Browser」で開いてください。既存チェックアウトを使用し、依頼がない限りGit worktreeは作りません。

道路データを更新する場合は、次を実行してください。

```bash
python3 scripts/fetch_osm.py
node scripts/prepare_sample.cjs
```

`fetch_osm.py` はOpenStreetMap公式APIから京都駅周辺のXMLを小さなタイルに分けて取得・重複排除し、道路、歩行制限、目印、標識、背景をJavaScriptへ変換します。`prepare_sample.cjs` は寺院・公園の種類を照合して同名の駅やバス停を除き、OSMの名所を近隣の道路へ補正し、後半の両訪問順で経路・CP数・コマ生成を検証してからサンプルを保存します。地点が欠ける場合や経路が成立しない場合は、架空の補間で埋めずにエラーにします。出典IDと補正距離はデータに残します。

外部から取得済みの公式XMLを使う場合:

```bash
python3 scripts/fetch_osm.py --input /path/to/kyoto.osm
node scripts/prepare_sample.cjs
```

更新した `site/data/kyoto-network.js` はサンプル検証後にコミットしてください。更新で取得データを作り直したらサンプル準備も再実行してください。

## 機能

- 道路をA*法で探索し、歩行禁止等を考慮（階段は距離を1.12倍で評価）
- 全交差点／道なり省略の切替。次のコマに似た省略交差点を復帰
- 類似判定は道の本数一致を必須とし、進入方向をそろえて枝道の角度差20度以内を比較
- 経由地は前半を直線距離で近い順、後半をランダムに訪問。入力順も選択可能
- 全体図にコマ番号を表示し、クリックで該当コマへ移動
- 看板・目印は交差点から10m以内、道路標識・信号は28m以内
- 手元のJPEG/PNG/WebPをコマのイラストと差し替え。保存用JSON・印刷・PDFに含める
- Google Street Viewの画像確認は任意。APIキーと課金設定が必要。キーは確認画面のメモリ内だけで使用し、画像・キーはJSONやPDFに含めない
- 京都版の保存キーとJSON形式を使用し、三浦版の保存データとは区別

基本のルート作成や手元の写真追加にGoogleの課金は不要です。道路幅、センターライン、勾配など未登録の情報は自動では判定できません。現地確認を行ってください。

類似判定は進入方向に対する枝道の左右を区別します。隣の交差点まで2m未満でも、道路の向きが読み取れれば判定に使います。実質的に長さのない道路だけを判別不能とします。復帰したコマの作成者向け説明には、比較先の最終コマ番号も表示します。

駐車場内通路（parking_aisle）の分岐は、本道の直進角度が25度未満で、ほかの枝道より20度以上直進に近い場合に限り、省略判定を続けます。駐車場通路をルート探索に追加する変更ではありません。駐車場側へ進む場合、曖昧なY字路、明示された通行制限・方向制限、標識がある場合は従来どおりコマを残します。旧保存データは訪問順と追記を保持して再計算します。類似交差点の省略防止判定や手動追記・CPにより、別の理由でコマが残る場合はあります。

信号機だけが省略不可の理由となる直進コマは、そのコマ自体を残しつつ、手前の類似交差点を復帰する際の比較先から外します。その信号コマを区間の境界とするため、手前の地点が信号の先のコマに似ていることを理由に復帰することもありません。信号の右左折コマ、信号機以外の標識、CPや手動追記でも残す地点は従来どおり類似判定を行います。単に28m以内に信号アイコンがあるだけではこの例外を適用しません。旧保存データは順序・追記を保持して新判定へ移行します。

## 交差点の人による評価

コマ地図を生成した後、上部の「交差点を評価」から別タブで評価画面を開けます。AIの学習ではなく、まず人の判断を集める画面です。

追加セット②〜⑤は評価画面の上部「評価セット」で選び、「選んだセットを開く」を押すだけで始められます。各100問をアプリに同梱しているため、JSONのダウンロード・読み込みやコース生成は不要です。初回は問題を読み込み、回答済みならブラウザに保存した回答を復元します。セットを切り替えても、元のセットと各回答はこのブラウザに残ります。評価者コードは引き続き `P001` を使ってください。

②・③は京都、④・⑤は三浦の三崎港周辺（本土側）です。④・⑤は各100問で、城ヶ島の道路を含めません。2026年11月3日取得の実OSM道路データを使用し、港・海南神社・向ヶ崎・宮川方面を含む範囲から抽出しています。④と⑤は同じ交差点IDや12m以内の地点を共有せず、京都の同梱セットとも重なりません。出典・抽出範囲・乱数は `site/data/evaluation-miura-source.json` に記録しています。問題は未回答で、AIの学習や判定条件は変更していません。京都で学習したモデルの地域外検証に使う場合、④・⑤を学習や閾値調整に使う前に評価してください。既存JSONとの互換性のため、三浦セットでも形式名は `kyoto-junction-evaluation` のままです。

回答後の持ち出しは、対象セットを開き「評価者・保存・JSON操作」→「評価JSONを保存」を押します。書き出すのは表示中の1セットです。ブラウザのサイトデータを削除した場合や別端末では自動復元できないため、バックアップは引き続き必要です。

1. 評価者コード（例：P001）と立場を設定します。実名は不要です。別の人には別のコードを使います。
2. 「次に表示されるコマ」と「その手前にある交差点」を比較します。候補側に正解の進路・写真・標識は表示しません。
3. 「明確に区別できる」「ギリギリ区別できる」「区別できない」「判断保留」のいずれかを選ぶと、自動保存して次へ進みます。理由を書く場合は選択前に入力してください。「前へ」で戻り、選択し直すと回答を修正できます。同じ選択肢を押し直しても保存できます。保存できなかった場合は次へ進まず、回答を画面内に保持してJSONに書き出せます。
4. 回答は評価専用のブラウザ保存領域に自動保存され、再読み込みで再開できます。「評価JSONを保存」で必ずバックアップしてください。容量不足時は画面内の回答を保ち、JSONへ退避できます。
5. 未回答の評価セットをJSONで配ると、別端末で同じ問題を評価できます。同じセットの別コードの回答は読み込みで統合します。同じコード・ペアに異なる回答がある場合は、競合として取り込みを中止し、現在の回答を保持します。別セットへ切り替えても、このブラウザに保存した回答を再開できます。バックアップにはJSONを保存してください。

「明確」「ギリギリ」は学習ラベル `omit`、「区別できない」は `keep` です。「判断保留」は `trainingLabel: null` とし、実運用での推奨は保持です。評価者の意見が割れたものを自動で多数決にまとめません。

回答前は現行ルールの判定を隠しています。回答後に確認を開くと閲覧時刻を記録し、その後の再回答は `blindAtDecision: false` として比較集計から除外します。判断保留も集計から除外します。時間は表示中の累計時間（`activeViewMs`）と最後の選択時刻までの時間（`decisionMs`）で、非表示のタブの時間を含めません。理由記入の時間も含み得るため、純粋な反応時間とは扱わないでください。

集計は、この評価者の回答について、現行ルールの誤省略数・不要な保持数・誤省略率・省略の適切さ・ギリギリ区別できる回答の省略率を表示します。分母が0の場合は「—」です。AIの精度はまだ集計していません。

### データと比較範囲

評価セットには、道なり判定で省略可能な交差点と、その後の基本表示地点（類似判定で復帰する前の、CP等により必須となる地点）とのペアを含めます。ルールが類似とするペアだけを選ばず、非類似のペアも含めます。直進の信号だけが保持理由の比較先は、現在のコース生成方針と同じく除外します。候補の表示順はセットごとに固定された並び替えを行います。

JSONの主な項目:

- `pairs[].modelInput`：候補と指示対象の道路形状・進入方向。候補には正解ルートを含めず、指示対象だけに進路を含めます。
- `pairs[].rulePrediction`：このペアの現行形状ルールによる `keep` / `omit`。人の回答前には表示しません。
- `pairs[].context`：元のコマID・コース上の位置など、照合用の情報です。
- `pairs[].splitGroups`：同じOSMノードの再通過・異方向をまとめるための識別子です。
- `responses[]`：ペアID、評価者コード・立場、4段階の判断、学習ラベル、理由、時間、回答更新日時・修正回数、ルールの閲覧履歴です。
- `source`：コース名、データ取得日、生成版、判定版、角度条件、抽出方法です。

将来のAIの入力には、`modelInput`から進入方向で正規化した形状特徴を作ってください。絶対座標、`context`、`rulePrediction`、評価者情報、人の正解ラベルを入力特徴に混ぜないでください。学習・評価の分割では同じ交差点を共有するペアを同じグループへまとめ、さらに未知ルートで検証します。OSM上で別ノードに分割された同一の現地交差点は、必要に応じて別途統合してください。

この集計は固定ペアの図形判定の比較であり、復帰処理を繰り返したコース全体の成績や、現地の見え方・安全性を保証しません。現地写真や実走での評価は別に必要です。写真やGoogle APIキーは評価JSONに含めず、評価の自動送信も行いません。

評価機能のテストは `node tests/evaluation.test.cjs` で実行できます。

### 100ペアの評価セット

新規の評価セットは100ペアで作成します。現在のコースだけでは不足する場合、訪問順の別案と京都サンプルの別訪問順から補充します。元のコマ地図のルート・順番・写真・追記は変更しません。100ペアを用意できない場合は、重複で水増しせずエラーとし、既存の回答を保持します。

すでに回答しているセットでは「回答を残して100ペアに増やす」を押してください。元の問題ID・回答・評価者を維持し、足りない問題だけ追加します。100ペア以上ある既存セットを勝手に減らすことはありません。新規セットが100ペアを超える場合は、重複する地点ペアを除いた上でコース全体から間隔をあけて100ペアを選びます。

追加分は「候補のOSMノードと指示対象のOSMノード」の順序付きペアで重複を除きます。同じ地点ペアの再通過や異なる進入方向も追加分では重複扱いにします。既存の回答済み問題は削除しません。補充した問題には `context.courseId`、出典情報には `source.supplementalCourses` を付け、回答後の確認にもコース名を表示します。

100ペアに増やしたJSONは形式バージョン2です。従来のバージョン1も読み込めます。同じセットIDなら、古い問題数のバックアップを読み込んでも、追加問題を消さずに統合します。回答の競合検出は従来どおりです。複数人で比較する場合は、まず100ペアを用意してJSONを書き出し、その同じセットを全員に配ってください。

## ローカルAIの学習とルールとの比較

回答者は一人でも開始できます。現在の実装は、道路形状から `keep` / `omit` を学習するCPU用の小さなランダムフォレストです。Googleへの課金や外部AIへの送信はありません。アプリの表示判定にはまだ適用せず、同じ検証用ペアで現行ルールと比較します。

### 回答済みセットを集める

1. 既存の回答を「評価JSONを保存」で退避します。評価者コードは引き続き `P001` を使います。
2. まず評価画面上部から同梱の「追加セット②」〜「追加セット⑤」を選べます。さらに集める場合は、別の経由地・道路を通るコースを生成し、新しい評価セットを作ります。同じコースのセットを繰り返すだけでは問題が重複します。
3. 各セットへ回答し、異なるファイル名でJSONを保存します。「ギリギリ区別できる」は省略、「区別できない」は保持です。判断保留・ルール閲覧後の回答は学習と検証から除外します。
4. ローカルの `local-ai/data/` に回答済みJSONを入れます。このフォルダ、学習結果、仮想環境はGitの対象外です。

同梱道路データから、既存セットと交差点が重複しない**未回答**セットも作れます。これは回答を自動生成する処理ではありません。

```bash
mkdir -p local-ai/data
node scripts/create_ai_evaluation.cjs \
  --exclude local-ai/data/set-01.json \
  --output local-ai/data/pending-02.json --seed 43
```

評価画面の「評価者・保存・JSON操作」→「評価JSONを読み込む」で `pending-02.json` を開き、回答後に `set-02.json` として保存してください。次のセットでは `--exclude` を繰り返し、既存の全セットを指定します。生成時は交差点IDと12m以内のノードを除外し、不足しても重複で水増ししません。作成するルートは評価問題の抽出用で、現地のイベントコースとしての下見は行っていません。

### 学習・検証する

Python 3.11以降とNode.jsが必要です。初回のみ仮想環境を作り、学習ライブラリをインストールします。

```bash
python3 -m venv .venv-local-ai
.venv-local-ai/bin/python -m pip install -r scripts/requirements-local-ai.txt
.venv-local-ai/bin/python scripts/local_ai.py train \
  local-ai/data/set-01.json local-ai/data/set-02.json \
  --evaluator P001 --output local-ai/run-001
```

`set-02.json` が未回答なら、まず `set-01.json` だけでも予備実験できます。複数セットはファイル名を並べて指定します。同一形状ペアの重複は除き、異なる回答がある場合は止めて確認を促します。異なる基準ルール版のデータは混ぜません。保管した同じセットの古いバックアップと最新版を同時に指定しないでください。

交差点の両端を結び、同じ `splitGroups` を共有するペアを連結成分にまとめます。さらに12m以内の交差点ノードをまとめ、同じ成分を丸ごと学習側か検証側の片方へ入れます。近接統合があるため検証25%は目安です。固定乱数42で一度分割し、成績が良くなる乱数を探しません。分割後の片側にラベルが一種類しかない場合や、全件が一成分の場合は追加データが必要です。

12mという距離は同じ現地交差点を完全に識別する保証ではありません。大きな交差点や別ノードで表現された地点は `split.json` と地図を照合し、必要なら `--merge-meters` を**検証前に**決めてください。近接統合は連鎖するため長い区間が一成分になる場合もあります。

出力先には次のファイルができます。既存結果への上書きは拒否します。

- `report.md`：ルールとAIの一致率、誤省略率、不要保持率、「ギリギリ」の省略率。
- `report.json`：分母・件数、乱数、近接距離、除外数、データの指紋、使用ライブラリ版。
- `validation.csv`：同じ検証用ペアについて、人の判断・ルール・AIを比較。
- `split.json`：学習・検証それぞれの交差点IDと元問題の照合情報。
- `model.json`：ローカルで読み込める学習済みモデル。pickle形式は使いません。

特徴量は、進入方向を基準とした各道路の8m・20m地点での角度を、左右を維持した円周上の分布に変換したものです。道路の本数も使います。絶対座標、ID、ルールの答え、人の回答、評価者情報は入力しません。現時点では進路矢印・信号・写真を使わないため、図の全情報を学習しているわけではありません。

`keep` の判定閾値は初期値0.5で固定します。`--keep-threshold` で変える場合は新しい実験として結果を残してください。一致率だけでなく、特に残すべき交差点の誤省略と、ギリギリ区別できる地点の省略を確認します。「全問省略」の比較結果もJSONへ出力します。

新しいセットを追加すると分割は変わり得ます。別の実験フォルダに結果を保存し、同じ実験内のルールとAIを比較してください。検証結果を見てモデルを調整した後の最終評価には、まだ使っていない別エリアの回答済みセットを確保します。一人分での数値はその評価者の図形判断への一致であり、他の参加者全体や現地での正答率を表しません。

保存済みモデルは、単一ペア（評価JSONの `pairs` の1要素）にも適用できます。

```bash
.venv-local-ai/bin/python scripts/local_ai.py predict \
  --model local-ai/run-001/model.json pair.json
```

テスト：`.venv-local-ai/bin/python -m unittest discover -s tests -p test_local_ai.py -v`。生成した評価セットは従来の評価画面で読み込み・回答できます。

同梱セットの検証：`node --test tests/builtin-evaluations.test.cjs`。ブラウザでの切替・回答保持・保存容量不足・再読み込み・表示サイズの回帰テストは、PlaywrightとChromiumのある環境でHTTPサーバーを起動し、`EVALUATION_TEST_URL=http://127.0.0.1:8000/site/evaluation.html node tests/evaluation-picker.browser.cjs` で実行できます（サーバーの起点はリポジトリ直下、Chromium実行ファイルは `CHROMIUM_PATH` で指定可能）。

他地域の評価セットを作る場合は、生成CLIへ `--network-json roads.json --region-name 三浦` を指定できます。`roads.json` は `nodes`・`ways`・`places`・`signs`・`timestamp` を持つ実道路データです。指定がなければ従来どおり京都データを使います。

選択時の自動保存のブラウザ回帰テストは、同じHTTPサーバーとPlaywright/Chromium環境で `EVALUATION_TEST_URL=http://127.0.0.1:8000/site/evaluation.html node tests/evaluation-auto-save.browser.cjs` を実行します。4選択肢、理由、修正、最終問題、二重クリック、キーボード、保存容量不足からの退避を確認します。
